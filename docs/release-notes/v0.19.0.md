# v0.19.0

Status: **Released**

Released on 2026-10-08.

v0.19.0 adds long-task runtime capabilities and addresses all thirteen findings
from the 2026-10-04 repository security scan. Public APIs remain pre-v1.0;
applications using Durable execution must coordinate the migration below.

## Breaking changes and migration

- `durable.HashContinuation` and `durable.ValidateCheckpoint` now require
  execution ID and immutable spec hash; checkpoint hashes also bind sequence.
- `durable.HashResult` now requires execution ID, spec hash and committed
  version, and binds the derived terminal status. Legacy content-only digests
  are rejected. Migrate checkpoint/result digests and stored response receipts
  together with backend and worker upgrades, using trusted record metadata.
  Follow the [backend migration](../security-hardening.md#backend-migration)
  and rerun `durable/contract.RunBackendContractTests`, including process reopen.
- Recursive typed tool input graphs are rejected at tool construction. Model
  tool names are limited to 256 bytes, and decoding/traversal/stream retention
  now enforce the documented [resource boundaries](../security-hardening.md#fixed-resource-boundaries).
- HTTPTool confines redirects to the original scheme and host even with a
  caller-supplied client. Its existing stricter redirect policy is preserved.

## Runtime capabilities

- Add model-backed working memory with protected instructions, recent complete
  tool exchanges, summary usage accounting and context-overflow recovery.
- Store large tool outputs as local artifacts with previews, range reads and
  search, so omitted evidence can be retrieved without rerunning the tool.
- Support ordered parallel tool groups, child token reservations and explicitly
  opted-in streaming overlap for complete, trusted read-only tool calls.
- Add in-memory asynchronous workers, task tools, completion delivery,
  retained follow-up context, cancellation and live steering.
- Continue explicit provider pauses without losing assistant state; retain
  actual outcomes of started writes while skipping obsolete pending calls.
- Add executable task verification through output guardrails and runnable
  examples for working memory, output retrieval, async workers, parallel tools,
  verification, streaming tools, pause continuation and live steering.

See [Agent execution](../agent-execution.md) for setup and ownership contracts.
The examples exercise execution mechanics with local providers; real-model
quality and production backend behavior require application verification.

## Security fixes

- Bind durable claim, attempt and finish responses to their issued request and
  validate decision-specific state before effects, replay or successful return.
- Bind checkpoint and result digests to their execution context and reject
  copied records or relabeled checkpoint sequences in the backend contract.
- Check JSON byte, depth, value and collection budgets before materializing
  continuation, attempt and provider payloads.
- Bound cumulative SSE bytes/frames and silent OpenAI/Anthropic retained state,
  including dense terminal arrays, blocks, citations and tool arguments.
- Bound tool-name suggestion work and feedback, skill directory traversal and
  recursive typed input handling. Prevent cross-origin redirect headers from
  reaching a second host.

The [security hardening report](../security-hardening.md) maps each finding to
its implementation and regression coverage. Historical cloud findings refer
to the scanned revision; these fixes have local verification and await a new
cloud scan.
